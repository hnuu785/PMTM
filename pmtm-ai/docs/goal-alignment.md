# PMTM 가사 모델 목표 정렬

## 1. 문서의 목적과 지위

이 문서는 PMTM 가사 생성 모델의 데이터, 학습, 보상과 평가를 하나의 목표에 정렬하기 위한 학습 계약서다.

- 제품 전체의 최종 비전은 [`docs/project-goal.md`](../../docs/project-goal.md)를 따른다.
- 이 문서는 그 비전 중 **한국어 8마디 랩 벌스 생성 모델**의 학습 기준을 정의한다.
- 모델 구조나 학습 방법을 바꾸더라도 이 문서의 목표와 통과 기준은 임의로 낮추지 않는다.
- 목표나 통과 기준을 변경할 때는 새로운 실험을 시작하기 전에 이 문서와 평가셋 버전을 함께 갱신한다.

표준 학습 경로는 `SFT → GRPO`다. SFT는 좋은 랩 가사의 기본 분포를 만들고, GRPO는 자동으로 측정 가능한 비트 적합성 제약을 강화한다.

## 2. 단일 학습 목표

> 사용자가 지정한 주제와 비트 조건에서, 각 줄이 한 마디 안에 랩 가능하고 목표 음절 범위를 지키며, 자연스러운 한국어와 의미 연결 및 라임을 갖춘 8마디 벌스를 생성한다.

모델 품질은 다음 우선순위로 판단한다.

1. 정확한 8마디 구조
2. 마디별 목표 음절 범위와 호흡 가능성
3. 사용자 주제 준수와 의미 연결
4. 자연스러운 한국어
5. 끝 라임과 내부 라임
6. 동일 줄, 끝단어와 구절 반복 억제

상위 조건을 위반한 출력은 하위 점수가 높아도 좋은 출력으로 인정하지 않는다. 예를 들어 라임 점수가 높더라도 한 마디 안에 발화할 수 없거나 주제와 무관하면 실패다.

## 3. 초기 적용 범위

초기 모델의 범위는 다음으로 제한한다.

- 한국어 중심 랩 벌스
- 4/4 박자표
- 정확히 8마디
- 한 줄을 한 마디에 대응
- 비트 분석기가 계산한 마디별 목표 음절 범위 사용
- 사용자가 지정한 하나의 주제 사용

BPM은 단독 품질 목표가 아니다. 같은 BPM에서도 half-time/double-time 해석, 드럼 밀도, 쉼과 발화 속도에 따라 적정 플로우가 달라지기 때문이다. BPM은 비트 분석기가 만든 `targetSyllableRange`와 `flowDensity`의 컨텍스트로 사용한다.

가이드 보컬 합성, 음소 duration과 세부 강세 생성은 이 학습 계약의 범위에 포함하지 않는다. 해당 단계는 텍스트 모델이 통과 기준을 만족한 이후 별도 파이프라인에서 다룬다.

## 4. 학습 입출력 계약

### 4.1 필수 입력

모든 SFT, GRPO, 평가와 서비스 추론은 다음 필드를 동일한 의미로 사용해야 한다.

| Field | Type | Meaning |
|---|---|---|
| `topic` | string | 벌스 전체가 다룰 사용자 주제 |
| `bpm` | number | 분석되거나 사용자가 확정한 BPM |
| `timeSignature` | string | 초기에는 `4/4`만 허용 |
| `bars` | integer | 초기에는 `8`만 허용 |
| `targetSyllableRange` | bar별 `min`, `max` | 각 마디의 허용 발음 음절 범위 |
| `flowDensity` | `sparse`, `medium`, `dense` | 비트 분석기가 결정한 상대적 발화 밀도 |
| `rhymeScheme` | 8개 라임 그룹 | 예: `AABBCCDD`, `ABABCDCD` |

구조화 입력 예시는 다음과 같다.

```json
{
  "topic": "포기하지 않고 서울에서 살아남기",
  "bpm": 90,
  "timeSignature": "4/4",
  "bars": 8,
  "targetSyllableRange": [
    { "bar": 1, "min": 12, "max": 16 },
    { "bar": 2, "min": 12, "max": 16 },
    { "bar": 3, "min": 12, "max": 16 },
    { "bar": 4, "min": 12, "max": 16 },
    { "bar": 5, "min": 12, "max": 16 },
    { "bar": 6, "min": 12, "max": 16 },
    { "bar": 7, "min": 12, "max": 16 },
    { "bar": 8, "min": 12, "max": 16 }
  ],
  "flowDensity": "medium",
  "rhymeScheme": ["A", "A", "B", "B", "C", "C", "D", "D"]
}
```

학습용 user prompt는 위 필드를 모두 명시해야 한다. 학습, GRPO와 실제 추론에서 필드명과 지시 문구를 다르게 사용하지 않는다.

### 4.2 모델 출력

모델은 다음 형식만 출력한다.

```text
첫 번째 마디 가사
두 번째 마디 가사
세 번째 마디 가사
네 번째 마디 가사
다섯 번째 마디 가사
여섯 번째 마디 가사
일곱 번째 마디 가사
여덟 번째 마디 가사
[End]
```

출력 규칙:

- 정확히 8개의 비어 있지 않은 가사 줄을 출력한다.
- 제목, 번호, `[Verse]`, 설명과 Markdown을 출력하지 않는다.
- 마지막 가사 줄 다음에 `[End]`를 한 번 출력한다.
- 실제 음절 수, 라임 점수, 라임 그룹과 타이밍을 모델이 출력하지 않는다.
- 음절 수, 반복률과 라임 준수 여부는 결정론적 후처리기가 계산한다.

## 5. 목표와 측정 방법의 연결

모든 목표는 데이터 라벨, 학습 단계와 평가 지표 중 적어도 하나에 연결되어야 한다.

| Priority | Goal | Required data | Main learning stage | Evaluation |
|---|---|---|---|---|
| 1 | 정확한 8마디 | 검증된 8마디 가사 | SFT, GRPO | 정확한 8줄 출력률 |
| 2 | 음절 범위와 호흡 | bar별 발음 음절 수와 목표 범위 | SFT, GRPO | bar별 범위 준수율, 실제 비트 랩 가능률 |
| 3 | 주제와 의미 연결 | 주제 라벨과 사람 검수 가사 | SFT, 선호도 학습 | 사람 주제 관련성 평가 |
| 4 | 자연스러운 한국어 | 자연스러움이 검수된 가사 | SFT, 선호도 학습 | 사람 자연스러움 평가 |
| 5 | 라임 | bar별 라임 그룹 | SFT, GRPO | 지정 스킴, 끝 라임과 내부 라임 점수 |
| 6 | 반복 억제 | 중복이 제거된 가사 | 데이터 필터, GRPO | 동일 줄, 끝단어와 n-gram 반복률 |

자동 지표가 없는 주제 관련성, 의미 전개, 자연스러움과 창의성을 GRPO reward로 대체하지 않는다. 해당 목표는 사람 평가나 검수된 선호도 데이터로 판단한다.

## 6. 데이터 계약

### 6.1 데이터 등급

학습 데이터는 다음 두 등급으로 구분한다.

#### `gold`

- 한 줄이 실제 한 마디에 대응하는지 사람이 확인했다.
- BPM, 박자표, 주제와 마디별 목표 음절 범위가 확인되어 있다.
- 한국어 자연스러움과 의미 연결을 사람이 검수했다.
- 라임 스킴 또는 bar별 라임 그룹이 기록되어 있다.
- 학습에 사용할 권한과 출처가 확인되어 있다.

`gold` 데이터만 비트 적합성과 조건 준수 능력의 정답으로 사용한다.

#### `weak`

- 현재처럼 원곡 가사를 줄 단위로 나눈 데이터다.
- 줄바꿈과 실제 마디의 일치를 보장하지 않는다.
- 곡 전체 BPM은 있지만 bar별 타이밍과 발화 밀도 정답이 없다.
- 주제, 목표 음절 범위와 라임 스킴이 검증되어 있지 않다.

`weak` 데이터는 랩 문체, 기본 한국어 표현과 라임 경향을 학습하는 보조 데이터로만 사용한다. `weak` 데이터의 줄 길이를 비트 적합성 정답으로 사용하지 않는다.

### 6.2 음절 수 기준

- 한글은 발음되는 한글 음절 블록을 기준으로 센다.
- 영어는 CMU 발음 또는 프로젝트의 영어 발음 변환 결과를 기준으로 센다.
- 숫자와 약어는 실제 읽는 형태로 정규화한 뒤 센다.
- 쉼표, 문장부호와 Markdown 기호는 음절로 세지 않는다.
- 추임새는 발음되면 음절 수에는 포함하되 라임 평가에서는 별도로 처리할 수 있다.

한글 한 글자와 영어 알파벳 한 글자를 같은 단위로 세는 문자 수 기반 길이는 사용하지 않는다.

### 6.3 분할과 중복 방지

- train, validation, test는 chunk가 아니라 곡 또는 녹음 세션 단위로 분리한다.
- 같은 아티스트의 표현을 평가셋에 누출하지 않도록 artist-disjoint 평가셋을 별도로 둔다.
- 한 곡이 학습 분포를 지배하지 않도록 곡당 chunk 상한을 둔다.
- 완전 중복과 near-duplicate를 모두 제거한다.
- 각 레코드에 `sampleId`, `groupId`, `artistId`, `sourceType`과 데이터 버전을 보존한다.

## 7. 학습 단계의 역할

### 7.1 SFT

SFT의 책임:

- 자연스러운 한국어 랩 분포
- 사용자 주제를 따르는 능력
- 8마디 형식과 `[End]`
- 기본적인 의미 전개
- 목표 음절 범위를 따르는 초기 능력
- 다양한 라임 스킴의 기본 분포
- 반복이 적은 가사 생성

SFT는 `gold`를 중심으로 학습하고 `weak`는 문체 보조 데이터로 사용한다. validation을 활성화하고 자동 지표와 사람 평가를 함께 기록한다. 마지막 체크포인트가 아니라 통과 지표가 가장 좋은 체크포인트를 선택한다.

### 7.2 GRPO

GRPO의 책임:

- 정확한 8줄과 `[End]`
- 마디별 목표 음절 범위 준수
- 지정한 라임 스킴 준수
- 동일 줄, 끝단어와 n-gram 반복 억제
- 빈 줄, 지나치게 짧거나 긴 줄 억제

GRPO reward에 포함하지 않는 항목:

- 주제 관련성을 흉내 낸 단순 키워드 점수
- 한국어 자연스러움에 대한 검증되지 않은 휴리스틱
- 창의성 또는 감정의 단일 자동 점수
- 특정 아티스트 문구와의 유사성을 보상하는 점수

SFT가 아래 진입 기준을 모두 통과하기 전에는 GRPO를 실행하지 않는다. GRPO reward가 상승하더라도 사람 평가나 비트 적합성이 하락하면 해당 모델을 채택하지 않는다.

## 8. 모델 승격 기준

### 8.1 GRPO 진입 기준

SFT 모델은 고정 validation/test 세트에서 다음 기준을 모두 만족해야 한다.

- 정확한 8줄 출력률 95% 이상
- 마디별 목표 음절 범위 준수율 70% 이상
- 완전 중복 줄이 없는 출력 95% 이상
- 사람 평가 주제 관련성 평균 4/5 이상
- 사람 평가 한국어 자연스러움 평균 3.5/5 이상

하나라도 만족하지 못하면 데이터, prompt 또는 SFT를 개선한다. GRPO로 SFT의 자연스러움이나 주제 준수 문제를 해결하려고 하지 않는다.

### 8.2 최종 모델 통과 기준

- 정확한 8줄 출력률 98% 이상
- 마디별 목표 음절 범위 준수율 85% 이상
- 완전 중복 줄이 없는 출력 99% 이상
- 동일 끝단어가 2회를 초과하지 않는 출력 95% 이상
- 고정 비트 30개 중 80% 이상에서 큰 수정 없이 한 마디 안에 랩 가능
- `exp-005 SFT` 대비 블라인드 선호도 60% 이상

모든 자동 평가는 베이스 모델, SFT와 GRPO에 같은 prompt, seed 집합과 생성 파라미터를 적용한다. 사람 평가는 모델 이름을 가린 상태로 진행한다.

## 9. 현재 학습과 목표의 간극

이 절의 수치는 현재 `prepared_dataset_v2.jsonl`과 `exp-005` 산출물 기준의 기준선이다. 데이터나 실험이 바뀌면 같은 분석을 다시 실행해 갱신한다.

### 9.1 BPM을 무시해도 되는 데이터

현재 2,868개 SFT 샘플에서 BPM과 현재 코드가 계산하는 평균 줄 문자 수의 Pearson 상관계수는 `0.0444`다.

- 80~90 BPM 샘플: 281개, 평균 줄 길이 `13.56`
- 130~140 BPM 샘플: 420개, 평균 줄 길이 `13.69`

두 구간의 차이가 사실상 없으므로 모델은 BPM을 무시해도 정답 분포를 학습할 수 있다. BPM만 prompt에 넣는 방식은 비트 적합성 학습으로 간주하지 않는다.

### 9.2 줄과 마디의 혼동

`app/training/prepare_dataset_v2.py`의 `make_chunks()`는 원곡 가사를 8줄씩 자른다. 원본 줄바꿈이 한 마디, 반 마디 또는 여러 마디인지 확인하지 않기 때문에 현재 8줄 chunk는 실제 8마디 정답이 아니다.

같은 파일의 `line_length()`는 `[가-힣A-Za-z0-9]` 문자 수를 센다. 영어 단어의 발음 음절과 문자 수가 다르기 때문에 이 값은 랩 발화 밀도 정답으로 사용할 수 없다.

### 9.3 조건이 없는 prompt

`app/lyric_prompts.py`의 현재 prompt는 BPM, 8줄, 자연스러운 라임, 일정한 호흡과 반복 억제만 지시한다. 함수가 받는 `genre`와 `mood`도 실제 prompt에 반영되지 않으며 `topic`, `targetSyllableRange`, `flowDensity`와 `rhymeScheme`은 없다.

따라서 현재 모델은 사용자 주제나 구체적인 비트 적합성 조건을 학습할 수 없다.

### 9.4 라임 기준 불일치

`prepare_dataset_v2.py`는 인접한 모든 줄의 끝 라임 평균으로 데이터를 필터링한다. 이 방식은 `AAAA`에 유리하고 `ABAB`처럼 비인접 줄이 짝을 이루는 스킴을 불리하게 만들 수 있으며 내부 라임을 평가하지 않는다.

또한 데이터 필터의 자체 한글 라임 계산과 `app/rhyme_scoring/rhyme_engine.py`를 사용하는 GRPO/서비스 라임 계산이 다르다. 데이터 선택, reward와 서비스 평가가 동일한 기준을 공유하지 않는다.

### 9.5 데이터 누수와 비활성 validation

`app/training/sft_qwen.py`는 완성된 chunk를 무작위로 train/eval에 분리한다. 동일 곡의 다른 chunk가 양쪽에 들어갈 수 있으며 현재 준비된 레코드에는 곡과 아티스트 식별자가 없다.

eval dataset을 만들지만 `eval_strategy="no"`이므로 실제 validation을 수행하지 않는다. `exp-005` SFT 로그에는 train loss만 있고 best checkpoint와 validation 지표가 없다.

### 9.6 목표와 어긋난 GRPO prompt와 reward

`app/training/grpo_qwen.py`는 `rhyme_density` 상위 200곡을 선택하지만 prompt에는 각 행의 BPM만 사용한다. 선택한 곡의 주제, 라임 구조와 가사는 GRPO 조건에 반영되지 않는다.

현재 reward는 인접 줄 끝 라임, 줄 수, `[End]`, 완전 중복, 2~4-gram 반복과 극단적으로 짧은 줄을 평가한다. 주제, 실제 음절 범위, 의미 연결, 자연스러움, 내부 라임, 라임 스킴과 지나치게 긴 줄은 평가하지 않는다.

### 9.7 혼합된 GRPO 실험 이력

`exp-005/grpo_qwen/checkpoint-300`의 기록에는 전체 로그의 `grad_norm=NaN`, `loss=0`, completion clip 비율 `0.8~1.0`과 정상 종료 길이 감소가 나타난다. 이 run은 유효한 품질 실험으로 사용하면 안 된다.

같은 실험 경로의 `checkpoint-450` 기록은 finite gradient와 낮은 clip 비율을 보이지만 validation과 best checkpoint가 없다. 수치적으로 정상인 학습이라는 사실만 알 수 있으며 가사 품질 개선의 증거는 아니다.

실패 run과 변경된 run을 같은 experiment 경로에 저장하면 코드, 설정과 모델 결과의 대응 관계를 신뢰할 수 없다.

### 9.8 평가셋 부재

`run_training.py`의 `run_eval()`은 BPM 90과 95 prompt를 각각 한 번 생성해 출력한다. 베이스/SFT/GRPO 비교, 고정 평가셋, 다중 생성 평균, 자동 지표와 사람 평가는 없다.

현재 평가 방식으로는 loss 또는 reward 변화가 실제 랩 가사 품질 향상인지 판단할 수 없다.

## 10. 실험 운영 원칙

### 10.1 실험 불변성

- 모든 실험은 새로운 experiment 이름을 사용한다.
- 기존 experiment의 checkpoint 디렉터리에 다른 설정의 run을 이어 쓰지 않는다.
- 데이터셋, prompt 또는 reward가 바뀌면 각각의 버전을 올린다.
- dataset hash, 베이스 모델 ID, adapter 시작점, prompt 버전, reward 버전, seed와 생성 설정을 저장한다.
- 학습에 사용한 commit과 작업 트리 변경 상태를 기록한다.

### 10.2 공정한 비교

- 베이스, SFT와 GRPO를 동일한 고정 평가셋으로 비교한다.
- 모든 모델에 같은 생성 횟수, temperature, top-p, token 제한과 seed 집합을 사용한다.
- 평균뿐 아니라 실패율과 분포를 기록한다.
- 자동 점수와 함께 대표 성공·실패 출력을 보존한다.
- 사람 평가에서는 모델 이름과 학습 단계를 공개하지 않는다.

### 10.3 승격과 중단

- 평가 결과가 없는 checkpoint는 서비스 모델로 지정하지 않는다.
- 마지막 checkpoint가 아니라 통과 기준이 가장 좋은 checkpoint를 선택한다.
- reward가 상승해도 사람 평가나 비트 적합성이 하락하면 모델을 승격하지 않는다.
- NaN, 모든 completion truncation, reward 분산 붕괴 또는 반복 급증이 나타나면 학습을 중단한다.
- GRPO가 SFT보다 최종 통과 지표에서 개선되지 않으면 SFT를 서비스 후보로 유지한다.

## 11. 목표 정렬 체크리스트

새 데이터셋, prompt, reward 또는 모델 실험을 시작하기 전에 다음을 모두 확인한다.

### Data

- [ ] 각 목표에 필요한 라벨이 실제 데이터에 존재한다.
- [ ] `gold`와 `weak` 데이터가 구분되어 있다.
- [ ] 줄과 실제 마디의 관계를 과장하지 않는다.
- [ ] 발음 음절 수를 사용한다.
- [ ] 곡·세션·아티스트 단위 누수를 막았다.
- [ ] 데이터 출처와 사용 권한을 확인했다.

### Prompt and output

- [ ] 학습, GRPO, 평가와 서비스가 같은 입력 필드를 사용한다.
- [ ] BPM과 함께 목표 음절 범위가 전달된다.
- [ ] 모델 출력은 정확히 8줄과 `[End]`다.
- [ ] 후처리로 계산할 값을 모델에게 출력하도록 요구하지 않는다.

### SFT and GRPO

- [ ] SFT가 주제, 자연스러움과 기본 랩 분포를 담당한다.
- [ ] GRPO reward는 결정적으로 측정 가능한 목표만 사용한다.
- [ ] SFT가 GRPO 진입 기준을 통과했다.
- [ ] reward 상승과 실제 품질 상승을 별도로 검증한다.

### Evaluation

- [ ] 고정 test set을 학습에 사용하지 않았다.
- [ ] 베이스, SFT와 GRPO를 같은 조건으로 비교했다.
- [ ] 음절 준수, 반복, 라임과 형식 지표를 기록했다.
- [ ] 주제, 자연스러움과 실제 랩 가능성을 사람이 평가했다.
- [ ] 모든 최종 통과 기준을 만족한 모델만 승격했다.

## 12. 정의의 완료 조건

PMTM 가사 모델의 목표가 정렬되었다고 말하려면 다음이 모두 성립해야 한다.

1. 제품이 요구하는 입력 조건이 학습 데이터와 실제 추론에 동일하게 존재한다.
2. 좋은 벌스의 각 조건을 어떤 데이터와 학습 단계가 담당하는지 명확하다.
3. 자동으로 측정할 수 없는 품질을 잘못된 reward로 대체하지 않는다.
4. 고정 평가셋과 사람 평가로 베이스 대비 개선을 증명한다.
5. 비트 적합성 최우선 통과 기준을 만족한 모델만 서비스 후보가 된다.

이 조건이 충족되기 전에는 “쫀득한 플로우”, “좋은 라임” 또는 학습 loss/reward 상승만으로 모델 품질이 개선되었다고 결론 내리지 않는다.
