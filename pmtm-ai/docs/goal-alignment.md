# PMTM 가사 모델 목표 정렬

## 1. 문서의 목적과 지위

이 문서는 PMTM 가사 생성 모델의 데이터, 학습, 보상과 평가를 하나의 목표에 정렬하기 위한 학습 계약서다.

- 제품 전체의 최종 비전은 [`docs/project-goal.md`](../../docs/project-goal.md)를 따른다.
- 이 문서는 제품 중 **한국어 8줄 랩 벌스를 생성하는 가사 LLM**의 책임만 정의한다.
- 가사 LLM은 비트에서 파생된 고수준 FlowBrief를 조건으로 발화 가능한 가사를 생성하고, 정확한 플로우 생성, 음절·음소 duration, 강세, 쉼, F0와 보컬 합성은 별도의 Flow/Audio 파이프라인이 담당한다.
- 모델 구조나 학습 방법을 바꾸더라도 이 문서의 목표와 통과 기준은 임의로 낮추지 않는다.
- 목표나 통과 기준을 변경할 때는 새로운 실험을 시작하기 전에 이 문서와 평가셋 버전을 함께 갱신한다.

표준 학습 경로는 `SFT → GRPO`다. SFT는 좋은 랩 가사의 기본 분포를 만들고, GRPO는 자동으로 판정할 수 있는 텍스트 제약만 강화한다.

## 2. 단일 학습 목표

> 사용자가 지정한 주제와 비트에서 파생된 FlowBrief를 조건으로, 자연스러운 한국어와 의미 연결을 유지하면서 끝 라임과 내부 라임을 활용하고, 동일한 단어와 구절의 과도한 반복 없이 발화 가능하고 편집 가능한 8줄 랩 벌스를 생성한다.

모델 품질은 다음 우선순위로 판단한다.

1. 정확한 8줄 구조
2. 사용자 주제 준수와 의미 연결
3. 자연스러운 한국어
4. FlowBrief 조건에서의 발화 가능성
5. 끝 라임과 내부 라임
6. 동일 줄, 끝단어와 구절 반복 억제

상위 조건을 위반한 출력은 하위 점수가 높아도 좋은 출력으로 인정하지 않는다. 예를 들어 라임 점수가 높더라도 주제와 무관하거나 문장이 부자연스러우면 실패다.

## 3. 가사 LLM과 플로우의 책임 경계

PMTM 제품은 최종적으로 사용자가 플로우를 들을 수 있는 가이드 랩 데모를 제공한다. 가사 LLM은 최종 플로우 타이밍을 결정하지 않지만, 비트에서 파생된 FlowBrief를 조건으로 받아 의미·라임 품질을 유지하면서 발화 가능하고 플로우를 설계하기 쉬운 가사를 생성한다.

플로우는 같은 가사를 비트 안에서 어떻게 발화할지에 대한 시간적 해석이다. 같은 BPM과 같은 가사에도 half-time, double-time, 당김음, 쉼, 강세와 구절 분할을 다르게 적용한 여러 유효한 플로우가 존재한다. 따라서 비트에서 하나의 정답 플로우나 정답 음절 수를 역산해 가사 LLM에 학습시키지 않는다. FlowBrief는 목표 마디 수, tempo 해석, 구간별 밀도, 필수 쉼, 강세 앵커와 허용 subdivision만 표현하며 정확한 박자 위치, 음소 duration, 강세 세기와 F0를 포함하지 않는다.

책임은 다음처럼 분리한다.

| Layer | Responsibility | Not responsible for |
|---|---|---|
| FlowBrief Builder | 비트 분석 결과와 사용자 선택을 가사 생성용 고수준 조건으로 요약 | 가사 생성, 정확한 음소 타이밍 확정 |
| 가사 LLM | 주제, FlowBrief 조건, 의미 전개, 자연스러운 한국어, 라임, 반복 억제, 발화 가능성, 8줄 형식 | 정확한 박자 배치, 음소 duration, 강세 세기, 쉼 길이, F0 |
| 결정론적 후처리 | 줄 수, 반복, 끝단어, 발음 음절 수와 라임 지표 계산 | 가사의 창의적 품질 판정, 플로우 생성 |
| Flow/Timing Planner | 최종 가사와 비트 분석 결과를 받아 하나 이상의 타이밍·강세·쉼 후보 생성 | 가사 LLM 학습 |
| Vocal/Mix | 타이밍에 맞는 가이드 보컬 합성과 비트 병합 | 가사 품질 학습 |

발음 음절 수는 편집 화면, FlowBrief 조건 준수와 Flow/Timing Planner에서 타이밍 후보의 과밀·과소 구간을 진단하는 값으로 사용할 수 있다. BPM별 고정 음절 수를 정답 라벨로 사용하지 않으며, 발화 가능성 reward나 모델 승격 기준에 포함하려면 실제 보컬 합성 범위와 사람 평가로 먼저 검증해야 한다.

## 4. 초기 적용 범위와 입출력 계약

### 4.1 초기 범위

- 한국어 중심 랩 벌스
- 정확히 8개의 가사 줄
- 사용자가 지정한 하나의 주제
- 선택적으로 분위기, 라임 강도와 라임 스킴 제공

8줄은 편집 가능한 텍스트 단위다. 각 줄이 실제 한 마디에 대응한다고 가정하지 않는다. 줄과 마디의 대응, 한 줄의 분할 또는 여러 줄의 결합은 Flow/Timing Planner가 비트 위에서 결정한다.

### 4.2 모델 입력

SFT, GRPO, 평가와 서비스 추론은 다음 필드를 동일한 의미로 사용한다.

| Field | Required | Meaning |
|---|---|---|
| `topic` | yes | 벌스 전체가 다룰 사용자 주제 |
| `lines` | yes | 초기에는 `8`로 고정 |
| `mood` | no | 원하는 정서와 어조 |
| `rhymeScheme` | no | 예: `AABBCCDD`, `ABABCDCD` |
| `rhymeStrength` | no | 라임을 얼마나 촘촘하게 사용할지에 대한 텍스트 스타일 조건 |
| `flowBrief` | beat-driven 생성에서는 yes | 목표 마디 수, tempo 해석, 구간별 밀도, 필수 쉼, 강세 앵커와 허용 subdivision을 담은 고수준 조건 |

원시 `bpm`, `timeSignature`, 비트 타임스탬프, 목표 음절 수, 정확한 박자 위치, 음소 duration, 강세 세기와 F0는 가사 LLM이 직접 확정하지 않는다. 비트 기반 생성에서는 이 분석값을 `flowBrief`로 요약해 전달하고, 텍스트 전용 생성에서는 명시적인 기본 FlowBrief를 사용한다.

구조화 입력 예시는 다음과 같다.

```json
{
  "topic": "포기하지 않고 서울에서 살아남기",
  "lines": 8,
  "mood": "긴장감 있지만 자신감 있게",
  "rhymeScheme": ["A", "A", "B", "B", "C", "C", "D", "D"],
  "rhymeStrength": "medium",
  "flowBrief": {
    "targetMeasures": 8,
    "tempoInterpretation": "half-time",
    "densityByMeasure": ["medium", "medium", "dense", "sparse", "medium", "dense", "medium", "sparse"],
    "requiredRests": [{"measure": 4, "region": "last-half-beat"}],
    "accentAnchors": [{"measure": 2, "beat": 3}, {"measure": 4, "beat": 3}],
    "allowedSubdivisions": ["8th", "16th", "triplet"]
  }
}
```

### 4.3 모델 출력

모델은 다음 형식만 출력한다.

```text
1. 첫 번째 가사 줄 (12음절)
2. 두 번째 가사 줄 (13음절)
3. 세 번째 가사 줄 (12음절)
4. 네 번째 가사 줄 (12음절)
5. 다섯 번째 가사 줄 (11음절)
6. 여섯 번째 가사 줄 (13음절)
7. 일곱 번째 가사 줄 (12음절)
8. 여덟 번째 가사 줄 (12음절)
```

출력 규칙:

- 정확히 8개의 비어 있지 않은 가사 줄을 출력하며, 각 줄의 시작에 마디 번호(`1.~8.`)를 표기하고 끝에 `(X음절)` 가이드를 포함한다.
- 제목, `[Verse]`, 설명, Markdown 지시어, 그리고 `[End]` 태그는 출력하지 않는다.
- 이 마디 번호와 음절 태그는 추론 엔진 내부의 `post_process_lyrics` 후처리기를 통해 최종 사용자 서비스 노출 시 자동으로 제거된다.

## 5. 목표와 측정 방법의 연결

모든 목표는 데이터 라벨, 학습 단계와 평가 지표 중 적어도 하나에 연결되어야 한다.

| Priority | Goal | Required data | Main learning stage | Evaluation |
|---|---|---|---|---|
| 1 | 정확한 8줄 | 검증된 8줄 가사 | SFT, GRPO | 정확한 8줄과 출력률 |
| 2 | 주제와 의미 연결 | 주제 라벨과 사람 검수 가사 | SFT, 선호도 학습 | 사람 주제 관련성·전개 평가 |
| 3 | 자연스러운 한국어 | 자연스러움이 검수된 가사 | SFT, 선호도 학습 | 사람 자연스러움 평가 |
| 4 | FlowBrief 기반 발화 가능성 | 비트 분석에서 파생된 FlowBrief와 사람 검수 또는 합성 검증 결과 | SFT, 후보 재순위화, 검증된 경우 GRPO | FlowBrief 조건 준수율과 발화 가능성 사전 점수 |
| 5 | 라임 | 라임 스킴 또는 라임 구간 라벨 | SFT, GRPO | 지정 스킴, 끝 라임과 내부 라임 점수 |
| 6 | 반복 억제 | 중복이 제거된 가사 | 데이터 필터, GRPO | 동일 줄, 끝단어와 n-gram 반복률 |

자동 지표가 없는 주제 관련성, 의미 전개, 자연스러움과 창의성을 GRPO reward로 대체하지 않는다. 해당 목표는 사람 평가나 검수된 선호도 데이터로 판단한다. FlowBrief의 고수준 조건 준수와 발화 가능성은 가사 LLM 평가에 포함하되, 정확한 타이밍과 합성 보컬 품질은 Flow/Audio 파이프라인에서 별도로 평가한다.

## 6. 데이터 계약

### 6.1 데이터 등급

#### `gold`

- 벌스의 주제와 8줄 경계가 확인되어 있다.
- 한국어 자연스러움과 의미 연결을 사람이 검수했다.
- 라임 스킴 또는 라임 구간이 기록되어 있다.
- beat-driven 샘플은 FlowBrief와 해당 조건에서의 발화 가능성이 검수되어 있다.
- 과도한 동일 줄, 끝단어와 구절 반복이 없다.
- 학습에 사용할 권한과 출처가 확인되어 있다.

`gold` 데이터는 가사 품질과 조건 준수 능력의 정답으로 사용한다. 실제 녹음과 마디 정렬 정보가 있더라도 가사 LLM의 플로우 정답으로 사용하지 않는다.

#### `weak`

- 현재처럼 원곡 가사를 줄 단위로 나눈 데이터다.
- 줄바꿈의 음악적 단위를 보장하지 않는다.
- 주제와 라임 스킴이 검증되어 있지 않다.
- 한국어 자연스러움과 의미 연결에 대한 사람 검수가 없다.

`weak` 데이터는 랩 문체, 기본 한국어 표현과 라임 경향을 학습하는 보조 데이터로만 사용한다. 줄 길이, BPM 또는 줄바꿈을 플로우 정답으로 사용하지 않는다.

### 6.2 후처리용 발음 음절 수

- 한글은 발음되는 한글 음절 블록을 기준으로 센다.
- 영어는 발음 사전 또는 프로젝트의 영어 발음 변환 결과를 기준으로 센다.
- 숫자와 약어는 실제 읽는 형태로 정규화한 뒤 센다.
- 쉼표, 문장부호와 Markdown 기호는 음절로 세지 않는다.
- 추임새는 발음되면 음절 수에 포함하되 라임 평가에서는 별도로 처리할 수 있다.

한글 한 글자와 영어 알파벳 한 글자를 같은 단위로 세는 문자 수 기반 길이는 사용하지 않는다. 발음 음절 수는 FlowBrief 조건 준수와 발화 가능성 진단에 사용할 수 있지만, BPM별 고정 음절 수를 SFT 정답이나 검증되지 않은 GRPO reward로 사용하지 않는다.

### 6.3 분할과 중복 방지

- train, validation, test는 chunk가 아니라 곡 또는 녹음 세션 단위로 분리한다.
- 같은 아티스트의 표현을 평가셋에 누출하지 않도록 artist-disjoint 평가셋을 별도로 둔다.
- 한 곡이 학습 분포를 지배하지 않도록 곡당 chunk 상한을 둔다.
- 완전 중복과 near-duplicate를 모두 제거한다.
- 각 레코드에 `sampleId`, `groupId`, `artistId`, `sourceType`과 데이터 버전을 보존한다.

## 7. 학습 단계의 역할

### 7.1 SFT

SFT의 책임:

- 자연스러운 한국어 랩 가사 분포
- 사용자 주제를 따르는 능력
- 정확한 8줄 형식(마디 번호 및 음절 태그)
- 기본적인 의미 전개
- FlowBrief의 고수준 밀도·쉼 조건을 수용할 수 있는 발화 가능성
- 다양한 끝 라임과 내부 라임의 기본 분포
- 반복이 적은 가사 생성

SFT는 `gold`를 중심으로 학습하고 `weak`는 문체 보조 데이터로 사용한다. validation을 활성화하고 자동 지표와 사람 평가를 함께 기록한다. 마지막 체크포인트가 아니라 통과 지표가 가장 좋은 체크포인트를 선택한다.

### 7.2 GRPO

GRPO의 책임:

- 정확한 8줄(마디 번호 및 음절 태그)
- 명시된 경우 지정 라임 스킴 준수
- 동일 줄, 끝단어와 n-gram 반복 억제
- 빈 줄과 비가사 메타 텍스트 억제
- 실제 합성 범위와 사람 평가로 검증된 경우에만 FlowBrief의 결정적 조건 준수 강화

GRPO reward에 포함하지 않는 항목:

- 원시 BPM이나 박자표에서 직접 역산한 고정 음절 범위
- 정확한 박자 위치, 음소 duration, 강세 세기, 쉼 길이와 F0
- 검증되지 않은 줄 길이 기반 플로우 또는 발화 가능성 점수
- 주제 관련성을 흉내 낸 단순 키워드 점수
- 한국어 자연스러움에 대한 검증되지 않은 휴리스틱
- 창의성 또는 감정의 단일 자동 점수
- 특정 아티스트 문구와의 유사성을 보상하는 점수

SFT가 아래 진입 기준을 모두 통과하기 전에는 GRPO를 실행하지 않는다. GRPO reward가 상승하더라도 사람 평가의 주제 관련성, 자연스러움 또는 전체 선호도가 하락하면 해당 모델을 채택하지 않는다.

## 8. 모델 승격 기준

### 8.1 GRPO 진입 기준

SFT 모델은 고정 validation/test 세트에서 다음 기준을 모두 만족해야 한다.

- 정확한 8줄 출력률 95% 이상
- 완전 중복 줄이 없는 출력 95% 이상
- 라임 스킴이 지정된 평가셋에서 스킴 준수율 70% 이상
- 사람 평가 주제 관련성 평균 4/5 이상
- 사람 평가 한국어 자연스러움 평균 3.5/5 이상

하나라도 만족하지 못하면 데이터, prompt 또는 SFT를 개선한다. GRPO로 SFT의 자연스러움이나 주제 준수 문제를 해결하려고 하지 않는다.

### 8.2 최종 모델 통과 기준

- 정확한 8줄 출력률 98% 이상
- 완전 중복 줄이 없는 출력 99% 이상
- 동일 끝단어가 2회를 초과하지 않는 출력 95% 이상
- 라임 스킴이 지정된 평가셋에서 스킴 준수율 85% 이상
- `exp-005 SFT` 대비 블라인드 가사 선호도 60% 이상

모든 자동 평가는 베이스 모델, SFT와 GRPO에 같은 prompt, FlowBrief, seed 집합과 생성 파라미터를 적용한다. 사람 평가는 모델 이름을 가리고 가사와 FlowBrief만으로 진행한다. 정밀 플로우 청취 평가는 Flow/Audio 파이프라인의 별도 승격 기준으로 관리한다.

## 9. 현재 학습과 목표의 간극

이 절의 수치는 현재 `prepared_dataset_v2.jsonl`과 `exp-005` 산출물 기준의 기준선이다. 데이터나 실험이 바뀌면 같은 분석을 다시 실행해 갱신한다.

### 9.1 FlowBrief로 사용할 수 없는 현재 BPM·줄 길이 신호

현재 2,868개 SFT 샘플에서 BPM과 현재 코드가 계산하는 평균 줄 문자 수의 Pearson 상관계수는 `0.0444`다.

- 80~90 BPM 샘플: 281개, 평균 줄 길이 `13.56`
- 130~140 BPM 샘플: 420개, 평균 줄 길이 `13.69`

이 수치는 현재 데이터의 BPM과 줄 길이만으로는 유효한 FlowBrief나 플로우 정답을 만들 수 없다는 근거다. 원시 BPM 조건을 더 강하게 학습시키는 대신 별도 Beat Analysis와 검증된 규칙으로 FlowBrief를 만들고, 정확한 비트 해석은 Flow/Audio 파이프라인이 담당한다.

### 9.2 줄과 마디의 혼동

`app/training/prepare_dataset_v2.py`의 `make_chunks()`는 원곡 가사를 8줄씩 자른다. 원본 줄바꿈이 한 마디, 반 마디 또는 여러 마디인지 확인하지 않기 때문에 현재 8줄 chunk를 실제 8마디 정답으로 사용할 수 없다.

같은 파일의 `line_length()`는 `[가-힣A-Za-z0-9]` 문자 수를 센다. 영어 단어의 발음 음절과 문자 수가 다르며, 어느 쪽도 단독으로 플로우를 정의하지 않는다. 현재 값은 가사 모델의 발화 밀도 정답이나 reward로 사용하지 않는다.

### 9.3 목표 조건이 없는 prompt

`app/lyric_prompts.py`의 현재 prompt는 BPM, 8줄, 자연스러운 라임, 일정한 호흡과 반복 억제를 지시한다. 함수가 받는 `genre`와 `mood`도 실제 prompt에 반영되지 않으며 `topic`과 `rhymeScheme`이 없다.

따라서 현재 모델은 핵심 목표인 사용자 주제, 명시적인 라임 스킴과 FlowBrief 기반 발화 가능성을 학습할 수 없다. 원시 BPM과 막연한 일정한 호흡 지시는 제거하고, 비트 분석에서 파생된 구조화 FlowBrief로 교체해야 한다.

### 9.4 라임 기준 불일치

`prepare_dataset_v2.py`는 인접한 모든 줄의 끝 라임 평균으로 데이터를 필터링한다. 이 방식은 `AAAA`에 유리하고 `ABAB`처럼 비인접 줄이 짝을 이루는 스킴을 불리하게 만들 수 있으며 내부 라임을 평가하지 않는다.

또한 데이터 필터의 자체 한글 라임 계산과 `app/rhyme_scoring/rhyme_engine.py`를 사용하는 GRPO/서비스 라임 계산이 다르다. 데이터 선택, reward와 서비스 평가가 동일한 기준을 공유하지 않는다.

### 9.5 데이터 누수와 비활성 validation

`app/training/sft_qwen.py`는 완성된 chunk를 무작위로 train/eval에 분리한다. 동일 곡의 다른 chunk가 양쪽에 들어갈 수 있으며 현재 준비된 레코드에는 곡과 아티스트 식별자가 없다.

eval dataset을 만들지만 `eval_strategy="no"`이므로 실제 validation을 수행하지 않는다. `exp-005` SFT 로그에는 train loss만 있고 best checkpoint와 validation 지표가 없다.

### 9.6 목표와 어긋난 GRPO prompt와 reward

`app/training/grpo_qwen.py`는 장르·BPM·주제 조합으로 prompt를 만들며, SFT 어댑터에서 시작해 GRPO를 수행한다.

현재 reward는 strict 포맷, 인접 마디 끝 라임 coverage, 완전 중복을 평가한다. 주제, 의미 연결, 자연스러움, 내부 라임은 별도 reward로 평가하지 않는다.

### 9.7 혼합된 GRPO 실험 이력

`exp-005/grpo_qwen/checkpoint-300`의 기록에는 전체 로그의 `grad_norm=NaN`, `loss=0`, completion clip 비율 `0.8~1.0`과 정상 종료 길이 감소가 나타난다. 이 run은 유효한 품질 실험으로 사용하면 안 된다.

같은 실험 경로의 `checkpoint-450` 기록은 finite gradient와 낮은 clip 비율을 보이지만 validation과 best checkpoint가 없다. 수치적으로 정상인 학습이라는 사실만 알 수 있으며 가사 품질 개선의 증거는 아니다.

실패 run과 변경된 run을 같은 experiment 경로에 저장하면 코드, 설정과 모델 결과의 대응 관계를 신뢰할 수 없다.

### 9.8 평가셋 부재

`run_training.py`의 `run_eval()`은 BPM 90과 95 prompt를 각각 한 번 생성해 출력한다. 베이스/SFT/GRPO 비교, 고정 평가셋, 다중 생성 평균, 자동 지표와 사람 평가는 없다.

현재 평가 방식으로는 loss 또는 reward 변화가 실제 랩 가사 품질 향상인지 판단할 수 없다. BPM별 샘플 출력은 가사 품질 평가를 대신하지 않는다.

## 10. 실험 운영 원칙

### 10.1 실험 불변성

- 모든 실험은 새로운 experiment 이름을 사용한다.
- 기존 experiment의 checkpoint 디렉터리에 다른 설정의 run을 이어 쓰지 않는다.
- 데이터셋, prompt 또는 reward가 바뀌면 각각의 버전을 올린다.
- dataset hash, 베이스 모델 ID, adapter 시작점, prompt 버전, reward 버전, seed와 생성 설정을 저장한다.
- 학습에 사용한 commit과 작업 트리 변경 상태를 기록한다.

### 10.2 공정한 비교

- 베이스, SFT와 GRPO를 동일한 고정 가사 평가셋으로 비교한다.
- 모든 모델에 같은 생성 횟수, temperature, top-p, token 제한과 seed 집합을 사용한다.
- 평균뿐 아니라 실패율과 분포를 기록한다.
- 자동 점수와 함께 대표 성공·실패 출력을 보존한다.
- 사람 평가에서는 모델 이름과 학습 단계를 공개하지 않는다.

### 10.3 승격과 중단

- 평가 결과가 없는 checkpoint는 서비스 모델로 지정하지 않는다.
- 마지막 checkpoint가 아니라 통과 기준이 가장 좋은 checkpoint를 선택한다.
- reward가 상승해도 사람 평가의 주제 관련성, 자연스러움이나 전체 선호도가 하락하면 모델을 승격하지 않는다.
- NaN, 모든 completion truncation, reward 분산 붕괴 또는 반복 급증이 나타나면 학습을 중단한다.
- GRPO가 SFT보다 최종 통과 지표에서 개선되지 않으면 SFT를 서비스 후보로 유지한다.
- 가사 LLM과 Flow/Audio 파이프라인의 실험, 버전과 승격 결과를 분리해 기록한다.

## 11. 목표 정렬 체크리스트

### Data

- [ ] 각 가사 목표에 필요한 라벨이 실제 데이터에 존재한다.
- [ ] `gold`와 `weak` 데이터가 구분되어 있다.
- [ ] 8줄을 실제 8마디라고 과장하지 않는다.
- [ ] BPM, 줄 길이 또는 음절 수를 플로우 정답으로 사용하지 않는다.
- [ ] 곡·세션·아티스트 단위 누수를 막았다.
- [ ] 데이터 출처와 사용 권한을 확인했다.

### Prompt and output

- [ ] 학습, GRPO, 평가와 서비스가 같은 가사 입력 필드를 사용한다.
- [ ] `topic`과 필요한 경우 `rhymeScheme`이 전달된다.
- [ ] beat-driven 생성에는 비트 분석에서 파생된 FlowBrief가 전달된다.
- [ ] 정확한 박자 위치, 음소 duration, 강세 세기, 쉼 길이와 F0를 가사 LLM에 요구하지 않는다.
- [ ] 모델 출력은 정확히 8줄과 `[End]`다.
- [ ] 후처리로 계산할 값을 모델에게 출력하도록 요구하지 않는다.

### SFT and GRPO

- [ ] SFT가 주제, 자연스러움과 기본 랩 가사 분포를 담당한다.
- [ ] SFT 또는 후보 재순위화가 FlowBrief 조건에서의 발화 가능성을 담당한다.
- [ ] GRPO reward는 결정적으로 측정 가능한 텍스트 목표만 사용한다.
- [ ] GRPO가 정확한 플로우 타이밍을 학습하거나 검증되지 않은 발화 가능성 점수를 최적화하지 않는다.
- [ ] SFT가 GRPO 진입 기준을 통과했다.
- [ ] reward 상승과 실제 가사 품질 상승을 별도로 검증한다.

### Evaluation

- [ ] 고정 test set을 학습에 사용하지 않았다.
- [ ] 베이스, SFT와 GRPO를 같은 조건으로 비교했다.
- [ ] 형식, 반복과 라임 지표를 기록했다.
- [ ] 주제, 의미 전개와 자연스러움을 사람이 평가했다.
- [ ] 플로우 청취 평가는 가사 모델 평가와 분리했다.
- [ ] 모든 최종 통과 기준을 만족한 모델만 승격했다.

## 12. 정의의 완료 조건

PMTM 가사 모델의 목표가 정렬되었다고 말하려면 다음이 모두 성립해야 한다.

1. 가사 LLM과 Flow/Audio 파이프라인의 책임이 입력, 학습, 평가와 배포에서 분리되어 있다.
2. 좋은 가사의 각 조건을 어떤 데이터와 학습 단계가 담당하는지 명확하다.
3. 자동으로 측정할 수 없는 품질을 잘못된 reward로 대체하지 않는다.
4. 고정 평가셋과 사람 평가로 베이스 대비 가사 품질 개선을 증명한다.
5. 의미·언어·라임 품질과 FlowBrief 기반 발화 가능성 기준을 만족한 모델만 서비스 후보가 된다.

“쫀득한 플로우”의 정확한 타이밍과 프로소디는 Flow/Audio의 청취 목표다. 가사 LLM은 그 타이밍을 직접 생성하지 않지만 FlowBrief를 고려해 좋은 가사와 발화 가능성을 함께 확보하고, 제품은 최종 가사에 여러 가능한 정밀 플로우를 부여해 들려준다.
